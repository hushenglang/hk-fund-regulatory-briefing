# 香港基金管理简报

项目源码仓库：`hushenglang/hk-fund-regulatory-briefing`，默认分支 `main`。
公开主页：<https://hushenglang.github.io/hk-fund-regulatory-briefing/>。
用户口中的“三知”是工作流名称；生成页面不显示“三知”品牌。

## 选择报告期

所有日期使用 `Asia/Hong_Kong`，以任务实际运行日期计算，不沿用模板日期。

- 周报：刚结束的完整周一至周日；若用户明确给定日期，使用给定范围。ID 为周日 `YYYY-MM-DD`。
- 季报：刚结束的完整自然季度；1、4、7、10 月的 1 日运行，分别覆盖上年 Q4、当年 Q1、Q2、Q3。ID 为 `YYYY-qN`。
- 使用本 skill 同目录 `scripts/report_period.py weekly|quarterly` 可取得日期、ID 和目录条目。相同报告期复用 ID，更新同一期，不重复新增。

## 取材与事实核验

先读仓库 `CONTENT_GUIDELINES.md`、`reports/catalog.json` 及同类型最近一期 HTML。模板提供样式与业务背景，不是当前事实来源。用户另附 Word 汇集时逐条核对重要项目；云端无法访问的本地附件不得声称已读。

业务重点：香港基金管理、私募股权、Pre-IPO、基石投资及二级市场资管。检索官方原文：SFC 新闻/通函/咨询及结论，HKEX 上市规则/纪律及市场公告，HKMA 监管文件；兼顾直接相关的 CSRC、SEC 更新及判例。法律 AI 以产品方/律所正式公告为先，可靠行业报道为辅，明确二手来源。

按实际发布日期筛选报告期，分别记录发布日期、事件日期、生效日期及实施期限。核对适用主体、规则状态、数值及单位。重要事项完整覆盖，不设固定条数或一页上限。合并同一事项的重复公告但保留来源；季度覆盖整季，不能只汇总最后一周。每一条保留直接可点击原文链接。

标题写清监管主体、动作和核心要求，避免“复杂产品”等看不出新闻内容的短标签。正文用简练要点与业务启示，区分直接适用义务和对基金的间接影响。严格区分涉嫌违法、调查、限制通知、停牌、行政/纪律处分、法院/MMT裁定与刑事定罪。不得把 MMT 市场失当行为裁定写成刑事定罪，不编造案号、金额或来源。

检索不到或无法核实的条目不填充旧新闻。说明实际检索范围和限制；大面积来源不可用、报告期不明或证据不足时保留已发布版本，报告失败，不发布冒充完整的报告。

## 内容与版式

- 简体中文、简约整洁、紧凑、暖白底、深色字体、细分隔线；标题“香港基金管理”，副标题注明简报类型和报告期。
- 纵向单栏、适合 briefing。01 监管更新在上，02 判例及执法在下；法律 AI 新闻作为最后一组简练 bullet points，有相关重要进展时加入。旧周报可保留原有内容，但新稿统一使用这套结构。
- 每条监管新闻依次向下排列：完整标题、日期与来源、要点、启示，不横排三栏。所有重要案件完整收录，按日期倒序。
- 案例表格五栏：序号、日期、监管／执法活动、处罚分类、执法要点及启示。处罚分类正文纯黑 `#000000`、粗体 `700`，屏幕和打印均保留。
- 沿用现有 HTML 模板；报告原稿保留 `<div class="period">报告期</div>`，由生成器替换成折叠历史导航。不要把生成后的导航再次写回原稿。
- A4 portrait 打印；表头跨页重复。打印隐藏交互导航，但保留报告期。手机端菜单不溢出，正文可阅读，案例表格可局部滚动。

## 归档、校验与发布

1. 在 `reports/<id>.html` 保存完整单文件原稿，不删除历史稿。按 ID 更新 `reports/catalog.json`，字段为 `id`、`label`、`title`、`type`、`periodEnd`；日期格式 `YYYY-MM-DD`。
2. `periodEnd` 决定最新一期，文件修改时间不参与排序。`scripts/build_home.py` 生成 `dist/index.html`、`dist/archive/<id>.html` 和 `dist/catalog.json`。已发布 ID 不改名。
3. 可用代码运行环境中执行 `python3 scripts/build_home.py` 与 `python3 scripts/validate_site.py`。检查链接、锚点、文章完整性、最新一期及归档；有浏览器能力时检查桌面/手机、展开菜单和旧版返回最新入口。不要虚构未执行的检查。
4. 用户请求发布或定时任务明确授权发布时，把核实后的 HTML 和目录更新提交到 GitHub `main`；现有 `.github/workflows/pages.yml` 自动构建、校验、发布 `dist/`。只保存草稿的任务不提交到线上。
5. 有本地 Git 认证时使用普通提交/推送；否则使用 GitHub 连接器读取最新分支 SHA 与 tree，以最新 tree 为 base，仅修改本期和目录相关文件，创建 commit，再带 expected SHA 更新 ref。冲突时重新读取并保留别人更新；禁止 force push。
6. 无本地运行环境的云端任务可通过连接器直接提交源稿与目录，依靠现有 CI 执行构建与校验。检查对应 commit 的 Actions 运行和最终发布状态；失败则报告具体原因，不声称上线。
7. 发布成功后读取线上最新一期和历史入口确认，给出主页、当期永久链接、报告期及简短重点；发布未完成时说明当前状态。

公开仓库仅存正式简报、公开来源、模板、脚本和维护文档。原始 Word、内部资料、凭据和私人文件不上传。GitHub Pages 自动发布不更新原 Sites 镜像，不需要同时发布 Sites 或变更现有访问配置。

## 云端执行

每次从 GitHub `main` 读取本 skill 和模板，而非依赖 Mac 路径或当前聊天记忆。GitHub 读取与写入权限、联网检索和运行环境是执行前提；缺失时明确报告，不绕过授权。此 skill 描述方法，本身不创建定时任务、不替代授权，也不保证任务平台一定提供写入能力。
